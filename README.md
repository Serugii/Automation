## Специфікація та розбиття на вимоги

Вихідна вимога: пеня 0,1 % на день, пільговий період 3 дні, максимум 50 % від суми боргу. Реалізовано по одній вимозі в такому порядку:

| №   | Вимога                                                                   | Помилка / результат         |
| --- | ------------------------------------------------------------------------ | --------------------------- |
| 1   | Некоректна сума боргу (від’ємна, `NaN`, `Infinity`) відхиляється         | `INVALID_DEBT`              |
| 2   | Некоректна кількість днів (від’ємна, дробова, `NaN`, `Infinity`)         | `INVALID_DAYS`              |
| 3   | Пільговий період: 0–3 дні прострочення                                   | пеня `0`                    |
| 4   | Від 4-го дня нараховується 0,1 % від боргу за кожен день понад пільговий | `борг × 0,001 × (днів − 3)` |
| 5   | Пеня не може перевищувати 50 % від суми боргу                            | `min(пеня, борг × 0,5)`     |
| 6   | Результат заокруглюється до двох знаків після коми (копійки)             | `round2(...)`               |

## Прийняті рішення

Вихідна специфікація неоднозначна, тому зафіксовано такі рішення (кожне закріплене тестами):

- Пеня нараховується за дні **після** пільгового періоду: на 3-й день вона дорівнює 0, на 4-й — за один день (0,1 %).
- 0,1 % береться від початкової суми боргу (проста пеня, без нарахування на пеню).
- Максимум 50 % досягається після 500 днів нарахування, тобто на 503-й день прострочення; далі пеня не зростає.
- Обмеження 50 % застосовується до заокруглення: спочатку `min`, потім `round2`.
- Борг `0` є коректним значенням (пеня `0`); кількість днів `0` також коректна.

## calcPenalty

```ts
calcPenalty(debt: number, daysOverdue: number): number
```

| Борг   | Днів  | Результат | Пояснення                       |
| ------ | ----- | --------- | ------------------------------- |
| 1000   | 0     | `0`       | пільговий період                |
| 1000   | 3     | `0`       | межа пільгового періоду         |
| 1000   | 4     | `1`       | перший день нарахування         |
| 1000   | 10    | `7`       | 7 днів × 1 грн                  |
| 123.45 | 4     | `0.12`    | 0,12345 → заокруглення          |
| 1000   | 502   | `499`     | на день менше за межу обмеження |
| 1000   | 503   | `500`     | рівно 50 % — межа обмеження     |
| 1000   | 10000 | `500`     | обмеження 50 %                  |

Некоректні дані відхиляються винятком:

| Вхід                                     | Помилка        |
| ---------------------------------------- | -------------- |
| борг від’ємний, `NaN`, `Infinity`        | `INVALID_DEBT` |
| дні від’ємні, дробові, `NaN`, `Infinity` | `INVALID_DAYS` |

Якщо некоректні обидва аргументи, першою перевіряється сума боргу.

## Історія комітів (цикли TDD)

| Цикл | Вимога            | Red                                     | Green                                     | Refactor                                                 |
| ---- | ----------------- | --------------------------------------- | ----------------------------------------- | -------------------------------------------------------- |
| 1    | Некоректний борг  | відхиляє некоректну суму боргу          | завжди кидає `INVALID_DEBT`               | —                                                        |
| 2    | Некоректні дні    | відхиляє некоректну кількість днів      | перевірка боргу, решта — `INVALID_DAYS`   | —                                                        |
| 3    | Пільговий період  | у пільговий період пеня дорівнює нулю   | перевірка днів, повертає 0                | валідацію винесено в `assertValidDebt`/`assertValidDays` |
| 4    | Нарахування 0,1 % | 0,1 % на день починаючи з 4-го дня      | `debt * 0.001 * (днів - 3)`               | константи `GRACE_PERIOD_DAYS`, `DAILY_RATE`              |
| 5    | Максимум 50 %     | пеня не перевищує 50 % від суми боргу   | `Math.min(пеня, debt * MAX_PENALTY_RATE)` | —                                                        |
| 6    | Заокруглення      | результат заокруглюється до двох знаків | `Math.round(... * 100) / 100`             | розділення на `calcRawPenalty` і `round2`                |

Повна історія: `git log --oneline` (гілка `lab3-variant3`).

### Приклад рефакторингу (цикл 6)

**Було:** одна функція одночасно перевіряла вхідні дані, рахувала пеню, застосовувала обмеження й заокруглювала результат.

**Стало:** розрахунок (`calcRawPenalty`: пільговий період, нарахування, обмеження 50 %) відокремлено від заокруглення (`round2`), а валідація — від обчислень (`assertValidDebt`, `assertValidDays`). `calcPenalty` лише об’єднує ці кроки.

**Навіщо:** кожна функція має одну відповідальність, їх можна тестувати й змінювати окремо (наприклад, змінити правило заокруглення, не чіпаючи розрахунок). Рефакторинг виконано на повністю зеленому наборі тестів, після нього всі тести пройшли.
